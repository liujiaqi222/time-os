# Time OS 产品方向草案 v0.3

**状态：**目标门槛与三幕式首次引导已确认；其余内容作为后续设计与实现的方向草案。尚未修改 `docs/prd.md` 或实现。
**日期：**2026-09-29

## 一句话定位

Time OS 帮用户先确定值得推进的目标，然后用可靠、易用的计时器开始执行、留下记录，并从长期的真实投入中获得继续行动的动力。AI 可以协助制定和维护计划；Web 主要用于执行与回看。

## 不可省略的门槛

首次执行前，实例中必须有至少一个 active 目标。用户可以自己制定，也可以在 Codex 或 Claude 中与 AI 讨论后写入 Time OS。连接 AI 是一条引导路径，不是使用 Web 的强制条件。没有 active 目标时，执行页不展示可用的开始按钮。

每次执行必须归属于一个 active 目标；不提供无目标计时或“先开始、以后归属”的绕过入口。可以没有 Task，但不能没有目标。目标与推进线的可执行状态继续由共享服务层验证，Web 与 MCP 遵守相同约束。

目标是用户需要理解的最小概念。首次引导不要求用户理解 Goal / Track / Task 三级结构、排序、Current Next 或 MCP。已有数据模型要求 Session 关联 Track，因此实现时可以在目标下建立默认推进线来承载第一次执行；此结构不作为额外表单步骤。AI 或用户以后可以细分推进线。

## 首次引导

```text
登录 / 实例环境检查
  → 第一幕：你想让什么发生？（自己输入 / 和 AI 一起想清楚）
  → 第二幕：让这个目标属于你（目标卡片、可选的个人理由）
  → 保存 / 确认已写入的目标
  → 第三幕：从现在的一小段开始（进入执行首页的计时器）
  → 用户主动开始第一次执行
```

部署与数据库检查仍属技术 setup；目标引导是面向用户的独立步骤。完成时区设置不能代替“已有目标”的判断。用户中途离开后回来，应回到未完成的引导，不重复创建目标。

### 已确认的体验原则

建立目标是产品体验的正式开场。每屏只呈现一个当前决定，使用邀请式文案、充足留白和即时视觉回应。目标标题、用户自己的理由与逐渐成形的卡片成为视觉中心；不展示状态、排序、推进线等管理字段。

首次引导的终点是：用户带着一个属于自己的目标，站在可以立即开始的位置。首次完整呈现这段仪式；日后新增目标使用更短的版本。已有 active 目标的用户日常直接进入执行页；全部目标已完成或归档时，提供建立新目标或重新激活目标的入口，足迹仍可访问。

### 路径 A：和 AI 一起制定

1. 选择 Codex 或 Claude。页面解释连接会让该 AI 读取和更新当前 Time OS 实例中的目标与任务。
2. 提供对应客户端的连接指引、Time OS 地址，以及可复制的配置内容。Token 由用户从部署环境取得并在客户端填写；Web 不读取、回显或写入浏览器存储中的真实 Token。
3. 用户在客户端完成连接。页面给出一段可复制的开场话术：先讨论目标和可执行的第一步，得到用户确认后再写入 Time OS。讨论过程留在 AI 客户端。
4. 页面提供「我已在 AI 中保存目标」并重新查询；读取到目标后回到第二幕，展示真实写入的目标卡片供用户确认。确认已有目标不再次创建；用户无需重填 AI 已写入的内容。仅连接成功、尚未写入目标时仍停留在引导状态。连接是否成功由客户端调用 Time OS 工具的结果确认；Web 只验证目标是否已经写入，不能仅凭点击按钮声称连接成功。若客户端连接失败，给出地址、认证和配置的定向排查；始终可以切换到自己制定。

连接配置使用逐步展开的辅助指引；配置完成后继续引导制定目标。AI 与手动两条路径最终使用同一张目标卡片，并衔接同一个执行首页。

MCP 已有创建 Goal、Track、Task 和读取 Dashboard 的能力。按 Codex / Claude 分开的连接步骤、客户端内的验证指令和目标写回后的引导页面仍需设计与实现。具体配置格式要在实现前对照当时的客户端版本验证。

### 路径 B：自己制定

**第一幕：你想让什么发生？**

页面中央邀请：「最近，有什么事是你真的想推进的？」用户用一句话输入目标。提供可点击并修改的示例，如「做出自己的第一个产品」「能用英语自如交流」「写完一直想写的故事」。输入内容即时形成目标卡片预览；标题是唯一必要的用户输入。同屏提供「和 AI 一起想清楚」入口。

**第二幕：让这个目标属于你。**

展示目标卡片并追问：「如果这件事做成了，你最期待的变化是什么？」用户可以写一句，也可以跳过。保存这句话，供目标详情日后展示；无需另填目标描述。卡片颜色或图案自动搭配，可轻量调整，不增加必填项。允许返回修改目标标题；保存成功后才进入第三幕，失败时保留用户已输入的内容。

### 共同终点：第一次执行

**第三幕：从现在的一小段开始。**

目标卡片收拢到计时器上方，展示：「目标已经有了。现在，为它留一小段时间。」直接呈现番茄钟与正计时，主按钮为「开始第一次执行」。可顺手填写第一步，也可在已有目标下直接开始；不强制创建任务。

第三幕就是日常执行首页的首次状态；不用再经过完成引导页、任务管理页或额外跳转。保存目标不会自动启动计时，必须由用户点击开始。

第一次执行结束并成功保存后，活动日历亮起第一个有记录的格子，并用实际时长反馈，例如「你已经为这个目标投入了 18 分钟」。引导中的卡片成形表达目标已建立；完成执行后的反馈表达真实投入，文案与状态一致。

仪式感来自内容成形、柔和过渡和即时回应，不使用等级、分数或强制观看的庆祝动画。动效应支持减少动态效果偏好，不延迟操作；键盘与移动端同样能完成全部流程。

## 日常 Web 结构

主导航收敛为 **执行**、**足迹**。设置通过头像或齿轮进入；完整的目标/推进线/任务维护和记录修正放在次级入口。执行页仍可以快速查看与切换当前任务，不需要进入管理页才能选择要做的事。

### 执行页

- 计时器位于页面中心。上方是当前目标与可选的下一步、计时模式；中央是大号时间和清楚的阶段状态；下方是开始/暂停/继续/结束。截图中的大计时区和就近配置可作为布局参考，但不引入其侧边栏、排行榜或标签体系。
- 有正在进行的计时：返回页面立即恢复相同的模式、阶段、时间和关联目标，主要按钮为「继续」或「暂停」。
- 无计时：默认使用上次选择的模式，展示一个「开始执行」主按钮。可快速切换目标/任务；没有 Task 时可在已有目标下进行自由执行。
- 配置在计时器旁以抽屉或轻量面板展开，不迫使用户离开执行页。旁边只保留「加一条下一步」等轻量动作。完整任务排序、状态批量维护和归档进入目标详情。
- 页面底部可以显示很轻的今日投入与足迹入口，不把统计卡片挤到开始按钮前面。

### 两种核心计时模式

| 模式 | 开始前 | 运行中 | 到达终点 |
| --- | --- | --- | --- |
| 番茄钟 | 选择专注时长、短休息、可选长休息和循环次数；初始建议 25/5 分钟 | 清楚显示「专注」或「休息」、当前轮次、倒计时和进度；都可暂停/继续 | 专注倒计时归零时给出「开始休息」「继续专注」「结束」；休息归零时给出「开始下一轮」「结束」；不悄悄启动下一阶段 |
| 正计时 Stopwatch | 不需要填写计划时长 | 从零向上计时，可暂停/继续，适合不确定长度的工作 | 用户主动结束并保存真实专注时长 |

专注时间和休息时间必须分开。休息不计入专注时长、活动日历或任务投入；番茄钟每段实际专注都留有可靠记录，多轮执行可以在界面上合并展示为一次连续过程。倒计时归零后，在用户选择下一步之前不继续暗中累计专注；若用户选择「继续专注」，后续时间要明确计入。允许提前结束并保留实际投入，不要求凑满一个番茄才承认这次执行。

开始后不在同一段计时中静默更换模式、目标或时长；配置调整作用于下一段。切换目标或结束整个循环要明确结束当前专注段。可选提示音/通知只作提醒，不决定服务端的实际计时状态。

时间与阶段以服务端保存的时间点为准；刷新、关页、换设备或后台标签页被限速后，都能恢复正确状态。番茄钟还需要持久化当前轮次、专注/休息阶段、阶段截止时间与暂停信息。当前 Session 只有可选 `plannedMinutes`，可显示倒计时或正计时；它尚不支持持久化休息、循环和阶段转换，因此不能只通过换一套计时器 UI 来宣称支持番茄工作法。

### 执行中与结束

执行中保留暂停、随手笔记和结束。结束首先保存这次真实投入。若关联任务，结束后提供「这一步完成了」和「下次继续」两个清晰选择；跳过等低频状态放入更多操作。笔记可选，不因没填写而阻止保存。完成后返回执行页，并给出刚记录的时长及足迹入口。

现有 Review Dialog 默认选择“任务完成”，并同时展示完成、继续、跳过、笔记和摘要。应重新评估默认值，避免一次普通的结束操作意外推进任务。

## 足迹页：让用户愿意继续

参考用户提供的活动日历布局，展示 Time OS 自己能可靠记录的行为：

- 首屏：本周实际执行时长、活跃天数、当前连续活跃天数，以及与上周的简单对照。
- 活动日历：按用户时区展示最近一年的每日有效执行时长。格子的深浅表达时长；悬停/点击能看到日期、时长和执行次数。无记录日与未来日期清楚区分。
- 下方：最近的执行记录，以及按目标查看投入的入口。记录的筛选、补录、纠错保留，但不占据足迹页首屏。

连续天数只描述真实记录，不给用户打“生产力分”。当天尚未执行时，不把昨天仍连续的记录立刻显示为失败。活动日历的日界线沿用当前 AppSettings 时区；暂停时间和已取消 Session 不计入。跨午夜按实际时间拆到两天。统计口径应与现有 Statistics Service 共享；它目前提供时段汇总和 `focusDays`，还缺每日序列与连续天数。

## 与现有产品的主要差异

| 现状 | 调整方向 |
| --- | --- |
| `/setup` 完成时间设置后即可进入主应用 | 技术 setup 后增加目标引导；无目标不能开始执行 |
| 首次 Today 要求先去计划页建立目标、推进线和任务 | 从首次引导建立目标；第一步可选，执行页不要求用户维护三级结构 |
| 今天、计划、回顾、设置为并列导航 | 执行、足迹为主；计划维护与设置为次级入口 |
| Today 卡片点开始后才进入独立计时页，现有计时只提供可选倒计时/正计时 | 执行页中心就是计时器；提供完整番茄钟和 Stopwatch 两种模式 |
| 回顾页首先呈现筛选和审计工具 | 足迹页首先呈现活动日历与继续行动的反馈；记录修正下沉 |
| 结束专注进入完整回顾弹窗 | 先可靠保存投入，再用极简方式决定任务状态 |
| 统计只有今日/本周汇总 | 增加每日序列、连续天数和目标维度的可视化 |

## 实施顺序与可验收场景

1. **目标引导闭环**：全新实例不能直接开始；手动路径只填标题即可保存目标并进入第三幕；个人理由和第一步均可跳过。AI 连接成功但未写入目标时不能进入可开始状态；真实目标写入后展示同一张卡片，确认不重复创建。中途退出可继续，返回编辑、保存失败重试和切换路径不丢失内容或重复创建目标。第三幕直接衔接执行首页，必须主动点击才开始计时；首次执行保存后显示真实时长与活动格子。已有目标的日常访问不重播引导；所有目标非 active 时不能开始新执行，但仍可查看足迹。
2. **核心计时与结束流程**：有目标无任务也能执行；有任务时开始关联正确任务。番茄钟完成专注→休息→下一轮，正计时可任意时长暂停/继续；提前结束、倒计时归零、刷新/关页恢复、跨设备恢复后的时长和阶段正确。休息不计入专注统计；结束默认只保存记录，不误完成任务；完成任务时下一步正确推进。原有 Session 记录保持可读。
3. **足迹页**：真实记录生成每日格子；跨午夜、暂停、取消、更正、时区切换后，日历与汇总一致。空数据状态能引导用户回到执行。
4. **入口整理**：移动低频管理操作后，用户仍能找到目标管理、补录与纠错；移动端导航同样以执行和足迹为中心。

## 已确认边界与实现衔接

已确认：“已有目标”是执行的硬门槛，第一步可以稍后补；建立目标采用有仪式感的三幕体验，AI 与手动路径汇合到同一个首次执行入口。

现有 Session 必须关联 Track；实现方案可在目标下自动建立承载执行的默认推进线，不向首次使用者暴露这个内部层级。后续实现需处理默认推进线与 AI 创建推进线的共存及重复请求；这些内部安排不增加用户的引导步骤。
