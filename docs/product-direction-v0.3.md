# Time OS 产品方案 v0.3 — MVP

**状态：**核心流程与 MVP 范围已确认，已同步到 [主 PRD v0.3](prd.md)；实现由 [T06–T10](tickets/README.md) 承接。本文不代表功能已上线。
**日期：**2026-09-29

**文档关系：**本文保留 v3 的体验方向；主 PRD 是当前行为规范，tickets 给出实施细节。v0.2 已存档，T01–T05 仅作历史参考。按用户最新要求直接重构，不做旧数据迁移或旧接口兼容。

## 一句话定位

Time OS 帮用户围绕目标开始执行、留下进展，并在下次打开时接着做。Web 主要用于执行与回看；AI 可以帮助制定和调整计划，用户也可以完全通过 Web 独立使用。

## 唯一核心链路

```text
确定目标 → 明确下一步 → 开始执行 → 保存进展 → 下次继续
                                      ↓
                              足迹：看见真实投入
```

“明确下一步”可以来自已有任务、上次留下的接续提示，或一句临时的执行意图，不要求增加表单步骤。目标必需，任务与文字输入均可选。

v3 的首要验收场景：用户周一建立目标、执行二十分钟、中途结束并留下接续提示；周三回来，能立即看到做到哪里、接下来做什么，并一键开始下一次执行。若周一只是暂停而未结束，周三应恢复原计时，而非创建第二次执行。

行为改变与专注管理框架用于改善默认路径，不分别变成用户需要维护的产品模块。

## 用户心智模型

| 概念 | 用户理解 | 关系 |
| --- | --- | --- |
| 目标 Goal | 我想实现什么 | 每次执行都必须归属一个目标 |
| 任务 Task | 为这个目标做的一件具体事情 | 可选；一个目标有多个任务，一个任务可分多次执行 |
| 执行记录 Session | 这次做了什么、投入多久、下次从哪里继续 | 必须关联目标，可选关联任务；保存真实时间和可选文字 |

没有正式任务时，可以写一句“这次想做什么”，也可以直接围绕目标执行。这句话属于本次执行记录，不自动创建待办，也不强制以后转换成任务。

Track 不进入 v3 运行模型或首次引导，任务与执行直接属于目标。移除旧 Track 依赖与接口，不保留隐藏默认 Track。未来是否增加可选组织能力不在本轮范围。

## 不可省略的门槛

首次执行前，实例中必须有至少一个 active 目标。用户可以自己制定，也可以在 Codex 或 Claude 中与 AI 讨论后写入 Time OS。连接 AI 是一条引导路径，不是使用 Web 的强制条件。没有 active 目标时，执行页不展示可用的开始按钮。

开始执行时，所属目标必须为 active；不提供无目标计时或“先开始、以后归属”的绕过入口。若关联任务，任务必须属于该目标且可执行。Web 与 MCP 遵守相同约束，服务端不能只依赖页面检查。目标之后完成或归档，不应使已有历史记录失去归属或消失。

不再为了适配旧模型，要求用户建立推进线或为每个目标自动创建隐藏的默认 Track。数据模型与服务端允许按新流程重构，执行能力直接以目标为基础。

## 首次引导

```text
登录 / 实例环境检查
  → 第一幕：你想让什么发生？（自己输入 / 和 AI 一起想清楚）
  → 第二幕：让这个目标属于你（目标卡片、可选的个人理由）
  → 保存 / 确认已写入的目标
  → 第三幕：从现在的一小段开始（进入执行首页的计时器）
  → 用户主动开始第一次执行
```

部署与数据库检查仍属技术 setup；目标引导是面向用户的独立步骤。完成时区设置不能代替“已有目标”的判断。用户中途离开后回来，应回到未完成的引导，不重复创建目标。

### 已确认的体验原则

建立目标是产品体验的正式开场。每屏只呈现一个当前决定，使用邀请式文案、充足留白和即时视觉回应。目标标题、用户自己的理由与逐渐成形的卡片成为视觉中心；不展示状态、排序、推进线等管理字段。

首次引导的终点是：用户带着一个属于自己的目标，站在可以立即开始的位置。首次完整呈现这段仪式；日后新增目标使用更短的版本。已有 active 目标的用户日常直接进入执行页；全部目标已完成或归档时，提供建立新目标或重新激活目标的入口，足迹仍可访问。

### 路径 A：和 AI 一起制定

1. 选择 Codex 或 Claude。页面解释连接会让该 AI 读取和更新当前 Time OS 实例中的目标与任务。
2. 提供对应客户端的连接指引、Time OS 地址，以及可复制的配置内容。Token 由用户从部署环境取得并在客户端填写；Web 不读取、回显或写入浏览器存储中的真实 Token。
3. 用户在客户端完成连接。页面给出一段可复制的开场话术：先讨论目标和可执行的第一步，得到用户确认后再写入 Time OS。讨论过程留在 AI 客户端。
4. 页面提供「我已在 AI 中保存目标」并重新查询；读取到目标后回到第二幕，展示真实写入的目标卡片供用户确认。确认已有目标不再次创建；用户无需重填 AI 已写入的内容。仅连接成功、尚未写入目标时仍停留在引导状态。连接是否成功由客户端调用 Time OS 工具的结果确认；Web 只验证目标是否已经写入，不能仅凭点击按钮声称连接成功。若客户端连接失败，给出地址、认证和配置的定向排查；始终可以切换到自己制定。

连接配置使用逐步展开的辅助指引；配置完成后继续引导制定目标。AI 与手动两条路径最终使用同一张目标卡片，并衔接同一个执行首页。

按 Codex / Claude 分开的连接步骤、客户端内的验证指令和目标写回后的引导页面需在实现时验证。引导呈现当时真实支持的连接方式，不假设存在一键安装插件。新 MCP 契约围绕目标、任务与执行设计，具体配置格式对照当时客户端版本确认。

### 路径 B：自己制定

**第一幕：你想让什么发生？**

页面中央邀请：「最近，有什么事是你真的想推进的？」用户用一句话输入目标。提供可点击并修改的示例，如「做出自己的第一个产品」「能用英语自如交流」「写完一直想写的故事」。输入内容即时形成目标卡片预览；标题是唯一必要的用户输入。同屏提供「和 AI 一起想清楚」入口。

**第二幕：让这个目标属于你。**

展示目标卡片并追问：「如果这件事做成了，你最期待的变化是什么？」用户可以写一句，也可以跳过。保存这句话，供目标详情日后展示；无需另填目标描述。卡片外观使用统一默认设计，不增加装饰配置步骤。允许返回修改目标标题；保存成功后才进入第三幕，失败时保留用户已输入的内容。

### 共同终点：第一次执行

**第三幕：从现在的一小段开始。**

目标卡片收拢到计时器上方，展示：「目标已经有了。现在，为它留一小段时间。」直接呈现番茄钟与正计时，主按钮为「开始第一次执行」。已有任务时展示第一步；没有任务时，可顺手写一句“这次想做什么”，作为本次执行的上下文，也可直接开始。新增正式任务是独立的可选动作，不因填写这句话而自动创建任务。

第三幕就是日常执行首页的首次状态；不用再经过完成引导页、任务管理页或额外跳转。保存目标不会自动启动计时，必须由用户点击开始。

第一次执行结束并成功保存后，活动日历亮起第一个有记录的格子，并用实际时长反馈，例如「你已经为这个目标投入了 18 分钟」。引导中的卡片成形表达目标已建立；完成执行后的反馈表达真实投入，文案与状态一致。

仪式感来自内容成形、柔和过渡和即时回应，不使用等级、分数或强制观看的庆祝动画。动效应支持减少动态效果偏好，不延迟操作；键盘与移动端同样能完成全部流程。

## 日常 Web 结构

主导航收敛为 **执行**、**足迹**。设置通过头像或齿轮进入，其中提供完整的目标与任务管理入口。任务查看、切换、快速添加和轻量编辑在相关目标或任务旁即可完成；记录修正从足迹的记录详情进入。管理操作按需展开，不把全部表单平铺出来，也不要求用户为常用的小调整进入设置。

### 执行页

- 计时器位于页面中心。上方是当前目标与可选的下一步、计时模式；中央是大号时间和清楚的阶段状态；下方是开始/暂停/继续/结束。截图中的大计时区和就近配置可作为布局参考，但不引入其侧边栏、排行榜或标签体系。
- 有正在进行的计时：返回页面立即恢复相同的模式、阶段、时间和关联目标，主要按钮为「继续」或「暂停」。
- 无计时：默认使用上次选择的模式，展示一个「开始执行」主按钮。可快速切换目标/任务；没有 Task 时可在已有目标下进行自由执行。
- 当前任务旁展示适用的接续提示；没有任务时展示目标下上次执行留下的上下文。不要把其他目标或已完成任务的提示误配到当前任务。
- 计时器下方用紧凑列表呈现少量其他待办，完整列表按需展开。执行期间收起待办，让当前内容与时间成为中心。
- 配置在计时器旁以抽屉或轻量面板展开，不迫使用户离开执行页。完整排序、状态维护和归档进入目标详情的次级操作。
- 页面底部可以显示很轻的今日投入与足迹入口，不把统计卡片挤到开始按钮前面。

### 下次打开时如何接上

1. 优先恢复全局正在运行或暂停的计时及其目标、任务、阶段和笔记。
2. 没有计时则沿用用户选择的目标与尚未完成的任务；日常默认承接上次工作。用户主动切换后记住新选择。
3. 任务已经完成或不可执行时，展示该目标下可执行的下一项待办；没有待办时，仍可在目标下直接执行。
4. 原目标已完成或归档时，回到其他可执行目标的选择；没有 active 目标时引导建立或重新激活目标，足迹仍可访问。

接续提示直接展示在开始按钮附近，不要求先打开历史详情。用户可随时切换，无需每天先选“今日重点”、填写计划或完成复盘。候选任务的排序与并发更新规则在 tickets 中明确，不能仅凭旧的 Track Current Next 决定首页结构。

### 两种核心计时模式

| 模式 | 开始前 | 运行中 | 到达终点 |
| --- | --- | --- | --- |
| 番茄钟 | 使用可直接开始的默认设置，初始建议专注 25 分钟、短休息 5 分钟；可调整时长与长休息设置，无需先配置循环计划 | 清楚显示「专注」或「休息」、当前轮次、倒计时和进度；都可暂停/继续 | 专注倒计时归零时给出「开始休息」「继续专注」「结束」；休息归零时给出「开始下一轮」「结束」；不悄悄启动下一阶段 |
| 正计时 Stopwatch | 不需要填写计划时长 | 从零向上计时，可暂停/继续，适合不确定长度的工作 | 用户主动结束并保存真实专注时长 |

专注时间和休息时间必须分开。休息不计入专注时长、活动日历或任务投入；番茄钟每段实际专注都留有可靠记录，多轮执行可以在界面上合并展示为一次连续过程。倒计时归零后，在用户选择下一步之前不继续暗中累计专注；若用户选择「继续专注」，后续时间要明确计入。允许提前结束并保留实际投入，不要求凑满一个番茄才承认这次执行。

默认设置开箱即用，并记住用户偏好。MVP 支持专注、短休息、长休息及基本设置，不提供复杂循环编排或多套预设管理。主 PRD 与 T08 已明确默认值及阶段行为；继续专注表示跳过休息后开始一个新的完整专注段。

开始后不在同一次执行中静默更换模式、目标或任务；时长配置在开始时快照，偏好调整作用于下一次执行，不改变当前过程的后续轮次。切换执行对象时明确结束并保存当前执行，再开始新的执行，避免记录归属混乱。到时可见反馈与可关闭的提示音只作提醒，不决定服务端的实际计时状态，也不承诺关页后系统通知。

时间与阶段以服务端保存的时间点为准；刷新、关页、换设备或后台标签页被限速后，都能恢复正确状态。整个实例同时最多保有一次未结束的计时过程，包括其中的休息和等待用户选择的阶段。番茄钟需要可靠保存轮次、阶段、截止时间、暂停与实际专注区间，不能仅依靠浏览器倒计时。服务端结构可按此重新设计。

### 执行中与结束

执行中保留暂停、随手笔记和结束。已有的打断记录能力可作为次级入口保留，不扩展为新的待办收集系统。

结束流程固定为：

1. 用户点击「结束」，服务端先保存实际时间与当前笔记；成功后展示刚记录的时长，计时停止。无需先填写 Review 表单。
2. 若关联任务，可选点击「任务已完成」。默认不修改任务状态；不操作就保持原样，不要求再点“下次继续”才能离开。
3. 可选留一句「下次从哪里继续」，保存为可在下一次执行时直接展示的接续提示。

时间保存、任务完成和接续提示分别给出清楚的保存结果；后两项失败不撤销已经成功保存的执行时间。结束失败不能假报成功或丢失输入，重试不能生成重复记录。自动保存与结束同时发生时不得用旧笔记覆盖新输入。明确完成任务后，重复提交不能重复推进下一步。

接续提示不自动创建任务，也不是必填总结。任务已完成时，其提示保留在原记录中；展示下一项任务时不将旧提示当成新任务的说明。

## 足迹页：让用户愿意继续

参考用户提供的活动日历布局，展示 Time OS 自己能可靠记录的行为：

- 首屏：少量真实投入摘要，如累计投入、本周投入与执行次数。连续天数不作为 MVP 必需指标或主要激励。
- 活动日历：按用户时区展示最近一年的每日有效执行时长。格子的深浅表达时长；悬停/点击能看到日期、时长和执行次数。无记录日与未来日期清楚区分。
- 下方：最近的执行记录与已完成的任务，以及按目标查看投入的入口。用户能看见具体做过什么。一次任务经过多次执行仍只完成一次，不能按 Session 数重复计算完成事项。记录的筛选、补录、纠错保留，但不占据足迹页首屏。

投入时长与完成事项并列呈现，不由时长或已完成任务比例推算“目标完成百分比”。不引入自定义领先指标、计划达成率、生产力或专注质量评分。没有投入的日期如实留白，不表达成失败；用户回来时仍能看见过去的积累。

活动日历按当前设置的时区计算；暂停、休息和已取消记录不计入。计时记录按实际专注区间跨午夜拆分，补录和更正按明确的声明口径处理，首页与足迹、MCP 使用同一计算。已完成或归档目标下的历史投入仍然可查。

## AI 与 Web 的能力边界

AI 负责辅助讨论与调整：读取目标、任务和执行记录，帮助用户决定下一步，将用户认可的调整写回。MCP 提供与 Web 等价的领域读写能力，包括目标与任务维护、执行控制、记录与接续提示、补录纠错和统计读取；不为页面手势或仪式动画创建工具。

Web 独立完成目标创建、任务增改、执行、记录查看和修正。未连接 AI 不影响核心链路。连接指引在首次引导和设置中可找到，MVP 不内置 AI 聊天、自动教练或周期复盘系统。

## MVP 范围与主动舍弃

| 环节 | 必须可用的能力 |
| --- | --- |
| 进入 | 三幕目标引导，手动与 AI 两条路径 |
| 准备 | 查看目标和任务，快速添加、轻量编辑、切换 |
| 执行 | 核心计时器、暂停恢复、随手笔记 |
| 结束 | 保存时间、可选完成任务、留下接续提示 |
| 返回 | 恢复当前计时，或接上上次工作 |
| 回看 | 活动日历、目标投入、执行记录、完成事项与纠错 |
| 调整 | Web 按需维护，AI 通过 MCP 读取和更新 |

本轮不新增：重复行动与习惯系统、每日重点对象或每日必填计划、最小行动专用模块、十二周周期管理、WOOP 表单、自定义领先指标、计划达成率、周期复盘系统、内置 AI 聊天与自动教练。用户仍可把简单的行动约定写入目标说明或与 AI 讨论，但这些内容不产生额外的排程、评分和管理功能。

## 与现有产品的主要差异

| 现状 | 调整方向 |
| --- | --- |
| `/setup` 完成时间设置后即可进入主应用 | 技术 setup 后增加目标引导；无目标不能开始执行 |
| 首次 Today 要求先去计划页建立目标、推进线和任务 | 建立目标即可开始；任务可选，Track 不作为使用门槛 |
| 今天、计划、回顾、设置为并列导航 | 执行、足迹为主；计划维护与设置为次级入口 |
| Today 卡片点开始后才进入独立计时页，现有计时只提供可选倒计时/正计时 | 执行页中心就是计时器；提供完整番茄钟和 Stopwatch 两种模式 |
| 回顾页首先呈现筛选和审计工具 | 足迹页首先呈现活动日历与继续行动的反馈；记录修正下沉 |
| 结束专注进入完整回顾弹窗 | 一次点击先保存投入，可选完成任务、留下接续提示 |
| 返回时缺少明确的接续体验 | 优先恢复计时或上次未完成工作，并就近显示接续提示 |
| 统计只有今日/本周汇总 | 增加活动日历、目标投入与完成事项，不引入评分体系 |

## 可验收场景

以下按用户链路组织，开发依赖顺序由后续 tickets 明确。

1. **目标引导闭环**：全新实例不能直接开始；手动路径只填标题即可保存目标并进入第三幕；个人理由和第一步均可跳过。AI 连接成功但未写入目标时不能进入可开始状态；真实目标写入后展示同一张卡片，确认不重复创建。中途退出可继续，返回编辑、保存失败重试和切换路径不丢失内容或重复创建目标。第三幕直接衔接执行首页，必须主动点击才开始计时；首次执行保存后显示真实时长与活动格子。已有目标的日常访问不重播引导；所有目标非 active 时不能开始新执行，但仍可查看足迹。
2. **无需先整理任务**：有目标无任务也能执行；填写“这次想做什么”只生成执行上下文，不新增 Task。关联任务时归属正确，一个任务可对应多次记录。任何路径都不能要求用户先建立 Track。
3. **可靠计时**：番茄钟专注→休息→下一轮，正计时可暂停/继续；提前结束、倒计时归零、刷新/关页、跨设备恢复后的时长和阶段正确。暂停、休息与到时等待不计入专注；并发操作不能生成两个未结束的计时过程。
4. **结束与下次继续**：一键结束无需填写回顾；默认不完成任务。结束重试不重复记录，笔记无竞态覆盖；任务完成或接续提示保存失败不丢失已保存时间。周一结束并留提示、周三回来能直接继续；周一只是暂停则恢复原计时。任务已完成时不把旧提示带给下一项任务。
5. **足迹页**：真实记录生成每日格子；跨午夜、暂停、休息、取消、更正、时区切换后，日历与汇总口径一致。能按目标看到记录与完成事项，取消记录不计入，历史缺失信息不伪装成精确数据；没有数据时引导回到执行。
6. **独立使用与入口**：不连接 AI 也能完成完整链路；连接后 Web 与 MCP 可读取和更新同一份数据。常用小调整就近可达，完整管理、补录与纠错仍可找到。桌面、移动端、键盘操作和减少动态效果模式均可完成流程。

## 已确认边界与实现衔接

已确认：目标是硬门槛，任务可选；三幕引导衔接执行首页；结束先保存，接续提示帮助下次回来；足迹呈现事实；Web 独立可用，AI 通过 MCP 辅助计划与调整。

前端页面与服务端均可重写。服务端围绕 Web 体验和 MCP 能力设计；复用旧代码是工程选择，不是产品前提。计时、状态约束、幂等与统计规则由两端共享的领域能力统一执行。

主 PRD 与 tickets 明确目标直接关联任务/执行的数据模型、下一步选择、接续提示、番茄钟阶段和 Web/MCP 契约。按新版本直接设计与建库，不承担旧数据转换、旧接口适配或旧路由兼容。所有实现细节服务于已确认链路，不增加用户操作或扩张 MVP 范围。
