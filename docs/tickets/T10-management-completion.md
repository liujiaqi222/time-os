## 交付结果

用户可以完全通过 Web 管理目标和任务、执行、回看与修正；AI 通过 MCP 具备等价能力。全站页面都采用执行优先的新结构，低频操作按需展开，旧 Track 与独立 Focus 结构不再残留。

本票包含具体页面开发，不是只跑一遍测试。各前置票应先交付自己的完整能力，本票补齐维护体验与跨页收尾。

## 实施步骤

### 1. 目标列表与详情

- [ ] `/goals` 从设置进入，默认 active Goal 列表；非 active 在清楚的筛选中可找。先看目标内容，不常驻创建 / 编辑表单。
- [ ] 新增目标复用 T07 简短版本，只有标题必填；目标理由 / 说明可选。已存在目标的编辑不重播首次仪式。
- [ ] `/goals/[id]` 先显示目标与待办，可查看关联投入与记录；提供“去执行”入口，目标无 Task 同样可开始。
- [ ] Goal 编辑、排序、完成、归档、重新启用均使用共用服务。已完成 / 归档只读，明确恢复后才可编辑其计划。
- [ ] 未结束计时阻止状态变更时解释具体目标 / Session，提供返回计时；不能只灰掉按钮或调用浏览器原生 confirm。
- [ ] 不创建 Track 表单或隐藏 Track。移除原 Track 路由、链接、说明和测试依赖。

### 2. 任务维护与选择

- [ ] 默认紧凑任务列表，快速添加只问标题；完整描述、资源、估计时长、note 在详情 / 抽屉内编辑。
- [ ] 批量输入一次最多 50 项，按输入顺序创建；失败指出问题并保留原文，不产生一半成功的隐式结果。
- [ ] 支持完成、跳过、归档、重新打开。非 pending 默认只读；reopen 不自动抢占选择。
- [ ] 正在执行的 Task 必须先结束当前 Session 再改终止状态，包括正计时、番茄休息和等待阶段。
- [ ] 拖拽排序有“上移 / 下移”替代，服务端验证完整合法 ID 集合；失败恢复权威顺序并提示。
- [ ] “执行这项”调用 selection / start 共用契约，不由页面私自设置 Current Next 或创建另一个 timer。已有未结束过程时按 PRD 的结束再开始路径处理。
- [ ] Task 完成与下一步选择保持事务语义，非当前完成不抢占；无待办的 Goal 不显示报错，允许直接执行。
- [ ] 目标 / 任务列表分页或有安全上限；页面不能假定一个目标只有几个任务。

### 3. 设置与账户入口

- [ ] 设置分为时间偏好、AI 连接帮助、目标管理入口和退出登录；不把技术字段散落在执行首页。
- [ ] timezone / weekStartsOn / 三种番茄时长 / 长休息开关读取与保存使用服务端 schema，成功 / 错误 / pending 可感知。
- [ ] 时区更新重新读取足迹、今日摘要、日期分组；不改 UTC 原始值。运行中修改计时偏好明确下一次执行生效。
- [ ] AI 帮助复用 T07 的 ChatGPT Plugin 连接指南与 `/mcp` endpoint；页面、响应与浏览器存储不出现 access / refresh token。
- [ ] 退出清理 Web 会话和本地引导草稿，仍保留服务端执行记录与未结束计时；重新登录后恢复状态。

### 4. 全站页面覆盖

逐项填写完成证据，不以只检查执行首页代替全站改版：

## 端到端最终验收

### A. 完全 Web 使用

空库 → 登录 / Setup → 手动建 Goal → 第一次执行 → 保存真实时间 → 留接续提示 → 次日回来继续 → 添加 / 完成 Task → 下一项 → 足迹回看 → 更正 → 归档 Goal → 历史仍在 → 新目标。

### B. AI 与 Web 接力

真实 MCP 创建 Goal / Tasks → Web 确认目标 → Web 开始番茄 → MCP 暂停 → Web 恢复并结束 → MCP 读取记录 / hint → 经用户指令调整待办 → Web 显示同一状态。

### C. 失败恢复

并发 start、到时旧 phase 命令、note 版本冲突、结束响应丢失、排序失败、补录重叠、目标状态冲突、会话过期。每项都应保留可恢复路径，不以清库或刷新丢输入作为唯一解法。

### D. 视觉与移动端

桌面及 375px 逐页验证覆盖表；长中文 / URL、空状态、错误、软键盘、模态滚动与 reduced motion。记录截图 / 录屏路径及发现后修复结果。
