# T07 — 三幕目标引导与 AI 写回

**类型：**首次用户端到端体验。

**依赖：**T06。

**规范：**[PRD](../../prd.md) §4、§5、§8、§9.4。

## 交付结果

全新用户通过手动输入或 AI 讨论建立第一个目标，在同一体验中来到真实执行首页。目标创建有仪式感，标题是唯一必填项，任务和 AI 都不是强制条件。连接成功但未写入目标不算完成引导。

## 当前代码入口

- `src/app/login/`、`src/components/login-form.tsx`、`src/app/setup/page.tsx`、`settings-form.tsx`。
- 新 `/onboarding` 与 T06 的目标卡片 / 执行页；`src/services/planning.ts` 或重构后的 Goal service。
- `src/auth/`、`src/services/settings.ts`、`src/mcp/server.ts`、README 的连接说明。

## 实施步骤

### 1. 明确访问与恢复状态

- [ ] 未登录 → 登录；技术 setup 未完成 → Setup；已有 active Goal → 执行页；无 active Goal → 引导入口。
- [ ] 无 active Goal 只阻止开始执行，不阻止足迹、设置或查看已完成目标。避免在整个认证 layout 上统一重定向，造成无法重新启用目标。
- [ ] active Goal 存在但没有 Task 时直接可执行；不能借无 Task 再把用户送回引导。
- [ ] 登录 / Setup 重写为简洁一致样式，保留原鉴权、时区与 schema 健康检查。Setup 不展示完整 MCP 技术配置作为日常使用门槛。
- [ ] 浏览器草稿按实例隔离，保存标题、可选理由与当前步骤；返回 / 刷新可继续。退出登录清除草稿；不把 token 放进去。
- [ ] 已保存目标由服务端返回 id，清除本地创建草稿；重试、后退、切换路径都不能重复创建。

### 2. 手动三幕

第一幕邀请“最近，有什么事是你真的想推进的？”以居中单输入和可编辑示例开始，输入即时形成目标卡片。

第二幕展示用户内容，可选回答“如果做成，你最期待的变化是什么？”保存到目标说明 / 理由。提供跳过；没有状态、排序、指标、期限、Track 或外观配置字段。

第三幕直接呈现同一执行首页，目标卡片收拢至计时器上方，主操作“开始第一次执行”。可选写本次 intent 或快速加正式 Task，二者明确区分。创建目标和到达第三幕都不自动启动。

- [ ] 目标保存需要明确成功，保存中防重复提交；失败保留所有输入。
- [ ] 文案、卡片成形与短过渡构成仪式感，不增加动画等待或必填字段。
- [ ] reduced motion 保留信息变化，取消非必要运动；可通过键盘和读屏完成。
- [ ] 本票阶段使用 T06 已可用的正计时；T08 接入后第三幕自然使用默认番茄 / 上次模式，不复制另一套计时器。
- [ ] 日后新建 Goal 使用同一内容规则的简短版本，不重播整个首次流程。

### 3. AI 路径

- [ ] 提供 Codex / Claude 的选择，说明客户端能够读取和更新该实例目标与记录。
- [ ] 实现前核对实际客户端支持的连接方式，形成可重复操作的连接说明；引用对应官方文档并记下验证日期。不要硬编码未经验证的格式或假“一键插件”。
- [ ] 显示当前实例 endpoint、可复制的占位配置与客户端填写位置。真实 token 从部署环境取得，不增加 Web token 读取接口。
- [ ] 提供开场话术：讨论目标与第一步，经用户认可后用 v3 工具写入；不默认批量生成几十项任务。
- [ ] 提供“检查已保存目标”，调用 Goal list；无结果明确说明尚未保存，保留切换手动入口。
- [ ] 一个结果显示目标卡片，多结果让用户选；用户确认只选择该 Goal，不重新创建。AI 已填任务 / 说明无需重填。
- [ ] 从 AI 返回时使用 selection_set 的自动语义接上已有 Task；目标无 Task 时 goal-only 可开始。
- [ ] 地址错误、401、客户端配置失败与“连接可用但还没创建目标”分别提供对应说明；Web 不声称能从一次按钮点击检测客户端连接。

### 4. 服务与 MCP

- [ ] Goal 创建使用 T06 的幂等服务。对同一创建操作返回同一 id；同名目标不是全局唯一键，不能仅按标题去重。
- [ ] AI 通过 `goal_create` / `tasks_create` / `selection_set` 完成写入；Web 与 MCP 同源数据，无专用 AI 私有 Goal 存储。
- [ ] 不新增“动画下一步”等 MCP 工具。引导草稿是 UI 状态，目标与选择才是领域状态。
- [ ] 浏览器检查目标后若 Goal 已被归档，服务端 start 仍拒绝，页面回到可恢复选择。

### 5. 第一次执行的正反馈

- [ ] finish 成功后展示真实时长，零时长不伪造一分钟。
- [ ] T09 完成前可显示由真实记录计算的当日活动小格；不渲染伪造的一年历史。
- [ ] T09 接入后复用同一活动数据源。读取活动失败不影响已保存的执行结果，也不让用户再次 finish。
- [ ] 不要求完成 Task、写 hint 或连接 AI 才承认第一次执行已记录。

## 状态验收表

| 状态 | 正确入口 / 行为 |
| --- | --- |
| 新实例，未完成技术 Setup | Setup，成功后进入目标引导 |
| Setup 已完成，无 Goal | 第一幕 |
| 草稿未保存，刷新 | 恢复草稿，仍不能执行 |
| Goal 已保存，响应丢失后重试 | 同一 Goal，进入第三幕 |
| AI 可调用，但目标列表空 | 留在 AI 引导，不能假成功 |
| AI 写入多个 Goal | 选择一个已有 Goal，确认不创建副本 |
| active Goal 存在且 Task 空 | 进入可开始的执行页 |
| 所有 Goal 完成 / 归档 | 可看足迹，可创建或重新启用 |

## 测试与运行证据

- Unit：访问状态解析、草稿恢复与清除、响应丢失重试、候选目标选择。
- Integration：Goal 创建幂等与 key 冲突、AI/Web 并发写入后读取、归档后的 start 拒绝。
- E2E：手动仅标题 → 执行；中途返回 / 刷新；保存错误再重试；所有目标非 active 时仍可访问足迹；375px 键盘遮挡检查。
- MCP：真实客户端完成连接与 Goal/Task 写入，再在浏览器确认进入执行；仅 mock Goal list 不能代替真实连接证据。
- Security：检查网络与浏览器存储不含真实 MCP token；保持现有 Cookie / 密码行为。
- 提供三幕桌面与移动端实际截图，验证文字过长和 reduced motion；运行公共检查。

### Acceptance checklist

- [ ] 不连接 AI、只填标题也能完成首次引导并开始执行。
- [ ] AI 路径真实可操作；未写目标不能过关。
- [ ] 创建与确认没有重复数据，自动保存草稿不自动创建目标。
- [ ] 第三幕就是 T06 的执行首页，没有另一套计时状态。
- [ ] 有目标的日常用户不反复经过引导。
- [ ] 页面具备仪式感，但没有新增必填管理字段或强制动画。

## 不在本票范围

内置 AI 对话、LLM key、OAuth 自动连接、token 管理后台、完整任务管理、习惯或复盘系统、番茄状态机、旧客户端兼容。
