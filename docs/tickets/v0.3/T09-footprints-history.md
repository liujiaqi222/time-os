# T09 — 足迹、目标投入与记录纠错

**类型：**统计与回看端到端功能。

**依赖：**T06、T08；首次反馈使用 T07 组件。

**规范：**[PRD](../../prd.md) §3.3–3.4、§7、§9。

## 交付结果

足迹页第一屏展示真实投入与活动日历，用户能按目标或日期看到做过什么、完成哪些任务，并在详情中补录、纠错或取消。首页、日历、历史和 MCP 对同一数据给出一致结果。

## 当前代码入口

- `src/services/statistics.ts`、`history.ts`、`src/shared/focus-intervals.ts`、`timezone.ts` 或替代模块。
- `src/app/(app)/history/page.tsx`、`history/actions.ts`、`src/components/history-view.tsx`。
- T06 / T08 的 intervals、timeBasis、Session 与 Task 完成时间；T07 首次反馈。
- `src/mcp/server.ts` 的 history / stats / log / update 工具与分页 schema。

## 实施步骤

### 1. 统一统计读模型

- [ ] 建立同一计算入口：期间汇总、按日序列、按 Goal 汇总、有效 Session 次数与已完成 Task。首页也调用它，不再维护独立算法。
- [ ] 查询统一 now / timezone / weekStartsOn；端点使用 UTC，本地日期边界通过时区函数计算，覆盖 DST。
- [ ] observed 按各 focus interval 与区间求交，正在运行的末段裁到 now / deadline；暂停 / 休息 / due 不增加投入。
- [ ] period Session 次数按 id 去重，每日次数按该日有正投入的 Session 去重；不能把每日次数求和当周期次数。
- [ ] completed Task 按其 completedAt 与当前 completed 状态计一次，reopen 不继续算完成；与 Session 次数分开。
- [ ] cancelled 排除，completed / archived Goal 下的记录保留。取消执行不自动反转 Task 完成。
- [ ] 返回明确的范围、timezone 与汇总单位（秒）。显示不足一分钟时如实呈现，不点亮无有效投入的格子。
- [ ] 年视图单次有界查询 / 批量聚合，避免逐日查询数据库；需要的 goalId / 时间 / status / interval 索引与分页一起交付。

### 2. 重写足迹页

- [ ] 顶部少量摘要：累计与本周投入、有效次数；日历位于主要区域，不先铺筛选表单。
- [ ] 最近一年活动日历显示日期、有效时长、次数，区分空白与未来；图例含单位且颜色不是唯一信息渠道。
- [ ] 键盘或点击日期打开当天记录；跨日 Session 即使开始于前一天，只要当天有投入就能找到。
- [ ] 下方为最近执行与完成事项，Goal 筛选按需展开；切换 Goal 后摘要、日历和列表使用一致过滤范围。
- [ ] 主时间线按 startedAt 的本地日期归组，一条 Session 只显示一次；番茄轮次在详情展开。
- [ ] 记录显示 Goal、Task 或 intent、有效时长、note / resumeHint；详情区分专注、休息、暂停、手动记录与时间更正。
- [ ] 筛选、补录、取消审计置于次级入口；详情内可改记录，不把大编辑表单常驻首页。
- [ ] 空状态引导回执行；目标为空时引导建立目标。加载错误可重试，不显示假的零累计。
- [ ] 375px 不缩小成无法点中的全年小格；使用清晰的月份切换或显式可滚动日历。长 Goal / Task 标题不溢出。
- [ ] T07 首次记录反馈与日历共用数据，不能首次庆祝展示一套本地假统计。

### 3. 补录与重叠确认

- [ ] 补录输入 Goal、正有效时长、可选 Task / intent / note / hint；end 默认 now，start 默认 end − duration。无需 Track。
- [ ] 历史可关联既有非 active Goal / 非 pending Task，只验证目标存在与 Task 归属，不重新启用计划或开始计时。
- [ ] 首次遇到重叠返回 `SESSION_TIME_OVERLAP` 与冲突摘要，不写入；用户明确确认后携带 allowOverlap 保存。
- [ ] 确认后在事务内重新检查，冲突上下文可能已变化；重复提交使用幂等 key，不新增同一补录。
- [ ] 重叠按声明时间范围判断，允许确认后各自累计；界面说明不会自动去重。
- [ ] manual 与 timer、web 与 mcp 保持两个独立维度，补录不伪装成实时计时。

### 4. 已完成记录纠错

- [ ] 运行中记录提示先结束；仅 completed 可改时间 / 归属。cancelled 只从审计入口查看，不恢复计时。
- [ ] 更正目标时明确重选 Task 或清空，不保留另一目标的 Task。验证有效时长 > 0 且不大于墙钟范围。
- [ ] 只改 intent / note / hint 不重算时间、不改变 timeBasis；文字版本冲突按 T06 规则处理。
- [ ] 修改时间 / 时长后采用 corrected 汇总覆盖。保留原 observed intervals 作原始来源，统计只计算当前 corrected 数据，不能双算或伪造新观察区间。
- [ ] corrected 和有非连续声明范围的 manual 按范围比例分配时长，使用累计分配差值或等效算法保证整数秒总和一致；UI 明确这是一条更正记录，不声称知道暂停发生位置。
- [ ] 单独取消记录必须说明从统计排除的影响，包括番茄所有段；不自动取消已完成 Task。
- [ ] 更正提交用版本校验，覆盖时间变化的重叠检查并排除自身；失败保留输入。
- [ ] 更正 / 取消 / hint 修改后刷新首页、日历、Goal 汇总与详情，不能只更新当前卡片。

### 5. MCP

`stats_get` 提供期间汇总、daily、byGoal；`sessions_list` 支持 Goal / Task / 日期 / entryMode / createdVia / cancelled 与 cursor；`session_get` 返回阶段 / 记录详情；`session_log/update/cancel` 使用同一校验。

需区分“按开始时间分页的主历史列表”和“与选中日期存在有效投入交集的日历详情”，在参数和描述中明确，不让调用者猜。列表限制每页 1–100，daily 查询限制至一年视图所需的有界范围；累计汇总不返回全部记录。

## 关键数值验收例

1. 23:50–00:10 正计时，无暂停：两天各 10 分钟，期间总量 20 分钟、次数 1；每日各显示次数 1。
2. 23:50–23:55 专注，暂停到 00:05，再专注到 00:10：两天各 5 分钟，不能各分摊 10 分钟。
3. 25 分钟专注 + 5 分钟休息 + 10 分钟专注后结束：35 分钟、一次执行；不因两段专注算两次。
4. 23:30–00:30 的 corrected 记录声明 30 分钟有效投入：两天各 15 分钟，标明更正依据；原始区间不再重复贡献。
5. 同一 Task 三次执行后完成：三次执行、一件完成事项；reopen 后不再算当前 completed。
6. 取消一条重叠 Session：只移除该 Session 的贡献，其他记录与独立 Task 完成保留。
7. 同一 UTC 数据切换时区 / weekStartsOn：日期与周汇总按新设置重算，原始区间不改。
8. 某日无记录 vs 今日正在计时：前者为空白，后者只贡献已经真实发生的区间。

## 测试与运行证据

- Unit：日期 / DST / 周边界、区间裁剪、日与周期去重、比例分配守恒、Task 完成口径。
- PostgreSQL integration：真实区间聚合、取消 / corrected 排除、重叠检查事务、并发补录幂等、分页稳定性。
- Contract：Web/MCP 同范围与同 now 返回相同秒数、次数、daily 与 byGoal。
- E2E：首屏日历 → 日期详情 → Goal 筛选 → 补录冲突确认 → 更正 → 取消审计；可见数据与数据库一致。
- 性能：用一年代表性记录、跨日 / 多阶段混合 seed 测有界查询，记录查询次数与响应耗时；不另建性能平台。
- 实际桌面 / 375px 日历和详情证据，键盘可访问日期；运行公共检查。

### Acceptance checklist

- [ ] 足迹首屏先看见积累，筛选和纠错为次级动作。
- [ ] 首页、日历、Goal 汇总和 MCP 共用口径且数值一致。
- [ ] 真实暂停位置影响跨日统计，休息和等待不计专注。
- [ ] 一次 Session 与一次 Task 完成不会被轮次或记录数重复计算。
- [ ] 补录、纠错、取消可靠可恢复，不破坏原始时间来源。
- [ ] 不新增 streak 必达、评分、目标百分比或领先指标体系。
