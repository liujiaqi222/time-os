# T08 — 完整番茄钟与跨端计时

**类型：**计时领域与执行页完整功能。

**依赖：**T06；推荐在 T07 后实施，复用引导第三幕。

**规范：**[PRD](../prd.md) §3.3–3.5、§6、§9。

## 交付结果

用户可在核心区域选择番茄钟或正计时。番茄钟完整支持专注、短 / 长休息、暂停恢复和提前结束。关页、后台限速、另一设备操作或网络重试都不会造成多记、漏记或重复轮次。

本票同时完成服务端状态与 Web/MCP 控制，不接受只换倒计时 UI 的交付。

- `src/shared/session-timer.ts` 或其替代模块、设置 schema 与持久化。
- `src/app/(app)/session-actions.ts`、`src/mcp/server.ts` 或新 adapter。

## 实施步骤

### 1. 阶段持久化与统一时钟

- [ ] Session 保持一次执行过程，内部阶段保存 kind（focus / short_break / long_break）、序号、配置快照、开始 / 暂停 / 截止时间与实际区间。
- [ ] Session 的 active / paused / completed / cancelled 与计时阶段分开，不能把 break 或 due 当成已结束而释放全局位置。
- [ ] focus running / paused / due，break running / paused / due 均有清楚有效状态和 allowedActions；due 不显示“继续倒计时”。
- [ ] 读接口根据 serverNow 和保存的截止点投影有效状态；到时后无客户端请求也不能多记。读工具不依赖写入才能返回准确值。
- [ ] 命令在同一事务中结算已到期阶段，再应用动作。锁顺序统一，阶段只关闭一次、轮次只增加一次。
- [ ] 客户端显示以服务端锚点校准，回前台 / 重连刷新。前端时钟与轮询失败不成为计时真相。
- [ ] 时间计算集中为可注入时钟的领域模块，测试加速不依赖真实等待，也不增加生产公开“设置服务器时间”参数。

### 2. 固定 MVP 行为

默认 25 分钟专注、5 分钟短休息；长休息默认开启，每完成四段完整专注提供 15 分钟长休息。时长可设 1–180 分钟整数，轮次间隔固定四段。配置在 Session 开始时快照。

| 场景 | 必须实现的行为 |
| --- | --- |
| focus 到时 | 在原截止点封闭专注区间，进入等待；不继续累计 |
| 到时后选择开始休息 | 从命令被服务端接受的时刻开始本轮应有的短 / 长休息 |
| 到时后选择继续专注 | 跳过休息，新开完整专注段；等待间隔不计入 |
| 休息中暂停 / 继续 | 只暂停休息倒计时，不影响已有专注量 |
| 休息中提前开始下一轮 | 结束休息，新开专注段；不补记剩余休息 |
| 休息到时 | 进入等待，直到主动开始下一轮 |
| 提前结束专注 | 保存已执行区间，不凑满一个番茄 |
| 结束整个过程 | 汇总所有有效专注，休息 / 暂停 / 等待排除 |
| 取消过程 | 所有段保留但整体从默认统计排除；界面说明影响 |

跳过休息不形成待补休息债务。完成段数只在专注到时增加；四段后若跳过长休息，第五段结束提供短休息。下一次 Session 轮次重新开始。

### 3. 幂等与跨端操作

- [ ] 新增 `session_advance`，显式 action 为 start_break / start_next_focus，要求 expectedPhaseId；不能依赖含糊 toggle。
- [ ] 同一阶段同一成功动作重试返回其结果；来自旧 phase 的另一动作返回 `STALE_SESSION_PHASE` 与当前状态，不操作新一轮。
- [ ] start_break 与 finish 并发、next_focus 与 cancel 并发、到时瞬间 pause 均只有一个可解释结果。先按截止点结算再验证动作，禁止产生负剩余时间。
- [ ] pause / resume 不通过先读后写的无锁窗口更新总时长；重复请求不生成重复区间。
- [ ] Web 与 MCP 共用状态解析、配置校验与命令；客户端返回信息包含 Session、phase、累计专注、剩余时间、完整段数、serverNow 与版本。
- [ ] 浏览器收到其他端更改后更新当前按钮和状态，不拿旧乐观状态覆盖权威数据。
- [ ] 每轮、休息、等待中的 Goal / Task 完成和归档仍受未结束约束保护。

### 4. 配置与 UI

- [ ] 中央区域直接可见“番茄钟 / 正计时”；无计时可切换并记住偏好。运行时显示固定模式，不允许静默切换。
- [ ] 时长、长休息开关在就近抽屉里；默认即可开始，没有运行前循环编排表单。
- [ ] 运行中若编辑偏好，明确“下次执行生效”；该 Session 的现有及后续阶段遵循其配置快照。
- [ ] 清楚显示专注 / 短休息 / 长休息 / 等待、轮次与时间。暂停保留当前阶段身份；休息不标成专注。
- [ ] 到时等待显示“开始休息 / 继续专注 / 结束”或“开始下一轮 / 结束”；不自动填充下一阶段的已执行时间。
- [ ] 提示音可关闭，关闭 / 浏览器拦截声音不影响状态。每个 phase 到时每个客户端至多提醒一次，重新渲染不能反复播放。
- [ ] 移动端窄屏、矮屏抽屉与长任务标题均可操作；Space 只在有 pause / resume 语义的阶段生效。
- [ ] 接入 T07 第三幕，新实例默认番茄钟；已有明确正计时偏好的用户保持该偏好。

### 5. 对其他读模型的影响

- [ ] T06 dashboard / 今日摘要只汇总实际 focus intervals；rest 和 due 的 Session 仍可返回为未结束，但贡献值不增长。
- [ ] `session_get` 返回完整过程及内部阶段供后续历史详情使用，执行次数仍为一次。
- [ ] completed Session 的 duration 与累计区间一致，数据模型能支持 T09 跨日统计。
- [ ] 更新计时设置的 Web/MCP schema、错误和实际能力说明，移除 plannedMinutes overtime 旧语义及相关测试。

## 必测时间场景

1. 专注 25 分钟后关页两小时再读取：只记 25 分钟，处于等待，不自动完成两小时的循环。
2. 10 分钟专注 → 暂停 7 分钟 → 继续 15 分钟：计 25 分钟，在正确新截止点到时。
3. 到时等待 3 分钟 → 开始 5 分钟休息 → 等待 2 分钟 → 下一轮：两段等待和休息均不计专注。
4. 第四段完成后提供长休息；重复读取 / 重试不能把四段变五段。
5. 同时 start_break 和继续专注：只形成一个下一阶段，另一请求拿到明确冲突。
6. 在休息中结束：保留此前全部专注，结束时长不加休息。
7. 23:55 专注、跨日暂停再继续：真实区间可准确分配两天，为 T09 提供 fixture。
8. 设置改成 50 分钟时另一设备仍在运行 25 分钟 Session：旧过程不变，新过程使用新值。

## 测试与证据

- Unit：阶段投影、截止点、剩余时间、轮次、长休息、allowedActions、配置边界。
- PostgreSQL integration：命令竞态、phase 幂等、全局位置、区间总量、到期后首个写请求结算。
- Contract：每个合法 / 非法 action 在 Web/MCP 结果一致；旧 phase 错误可恢复。
- E2E：完整一轮及第四轮长休息、提前结束、暂停刷新、到时前关页后再开、多标签接管、声音关闭；使用受控服务端时钟或测试专用短时配置。
- 实际运行观察后台 / 前台切换和音频权限失败；提供运行、暂停、到时等待、休息的桌面与 375px 证据。运行公共检查。

### Acceptance checklist

- [ ] 两种模式真实可用，首次默认值无需配置即可开始。
- [ ] 关闭页面后到时不多记，休息 / 暂停 / 等待零专注贡献。
- [ ] 多轮只形成一个可查看 Session，阶段数据可靠保存。
- [ ] 并发 / 重试不会开出两个阶段或重复轮次。
- [ ] Web 与 MCP 交替操作后显示和数据库一致。
- [ ] 没有把番茄轮次、时间长度或提前结束解释为质量评分。
